# Security

## Reporting a vulnerability

Report suspected vulnerabilities privately through GitHub's **Report a vulnerability** button
(Security tab → Advisories). Do not open a public issue for a security problem.

Please include the affected version or tag, what you did, what happened, and what you expected.
We aim to acknowledge a report within five working days.

## What never goes in an issue, PR or discussion

- Secrets of any kind: tokens, client secrets, connection strings, workspace URLs or IDs.
- Real data, real schemas, real column names or real glossary terms from your organisation.
  Reproduce problems with the bundled synthetic data (`python -m synthetic.generate_data`).
- Screenshots that show any of the above.

## Supported versions

Only the newest tag gets fixes. A fix ships as a new patch tag (for example v0.1.1); published
tags are never moved or rewritten.

## Design notes relevant to security

- Model output never grants access. The LLM proposes metadata; an owner approves it, and grants,
  column masks and row filters are generated by deterministic code from rows in the `gov` schema.
- No raw column values are sent to the LLM: prompts carry profile statistics and pattern hits only.
- Governance jobs that change access run as a dedicated CI service principal, never as a person.
